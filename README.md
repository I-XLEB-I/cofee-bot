# Coffee Bot

Telegram-бот для учета обслуживания точек, закупок, ревизий и проезда с хранением данных в Google Sheets.

## Быстрый старт

1. Создай и активируй виртуальное окружение:
   - `python3 -m venv .venv`
   - `source .venv/bin/activate`
2. Установи зависимости:
   - `pip install -r requirements.txt`
3. Подготовь переменные окружения:
   - `cp .env.example .env`
   - заполни значения в `.env`
4. Проверь, что сервисный ключ Google доступен по пути из `CREDENTIALS_FILE`.
   - локально можно использовать `credentials.json` в папке проекта
   - в проде используй абсолютный путь вне репозитория, например `/etc/coffee-bot/credentials.json`
5. Запусти бота:
   - `set -a && source .env && set +a && python3 bot.py`

## Переменные окружения

- `BOT_TOKEN` — токен Telegram-бота
- `SPREADSHEET_ID` — ID Google-таблицы
- `PHOTO_CHAT_ID` — обязательный chat id для отправки фото
- `CREDENTIALS_FILE` — путь к JSON сервисного аккаунта Google; в проде держи файл вне папки проекта
- `USERS_JSON` — необязательный JSON-словарь вида `{"1395822345":"Матвей"}`; если переменная не задана, бот читает сотрудников из листа `Пользователи`
- `ALLOWED_USER_IDS` — список разрешённых Telegram user id через запятую; если переменная не задана, бот берёт id из `USERS_JSON` или листа `Пользователи`
- `ALLOWED_GROUP_CHAT_IDS` — список разрешённых group/supergroup chat id через запятую
- `GROUP_REPORT_DRAFT_TTL_SECONDS` — время жизни черновиков из групповых сообщений (в секундах)
- `CARD_MESSAGES_AUTO_CLEANUP_SECONDS` — автоочистка карточек точек в чате (в секундах, `0` выключает)
- `OPERATIONS_API_URL` — полный HTTPS-адрес защищённой оперативной сводки, обычно `/internal/operations/points`
- `OPERATIONS_API_TOKEN` — отдельный токен только для чтения оперативной сводки; не используй здесь MCP/admin-токен
- `OPERATIONS_API_TIMEOUT_SECONDS` — тайм-аут запроса оперативной сводки, по умолчанию 5 секунд
- `OPERATIONS_CACHE_TTL_SECONDS` — локальный кэш сводки в боте, по умолчанию 60 секунд
- `OWNER_AI_INTERNAL_URL` — полный HTTPS-адрес versioned read-only API, обычно `/internal/owner-ai/v1/query`
- `OWNER_AI_INTERNAL_TOKEN` — отдельный service-to-service токен длиной не менее 32 символов; не переиспользовать MCP, Telegram, operations или provider-токены
- `OWNER_AI_TIMEOUT_SECONDS` — тайм-аут одного вопроса, по умолчанию 25 секунд

## ИИ-аналитик

При настроенных `OWNER_AI_INTERNAL_URL` и `OWNER_AI_INTERNAL_TOKEN` в личном
меню появляется кнопка `ИИ-аналитик`. В разрешённой рабочей группе сотрудник
вызывает его только явной командой:

```text
/ai Продажи Гагарина сегодня
```

Обычные сообщения группы не отправляются в ИИ и не расходуют лимит.
`telemetron-mcp` повторно проверяет Telegram user ID и назначает права:

- владелец получает полный текущий read-only набор аналитики;
- сотрудник видит только продажи, товары, способы оплаты, состояние
  терминалов и последние продажи;
- клиентские заявки, выплаты, аренда, бухгалтерские изменения, возвраты и
  команды терминалам сотруднику недоступны.

`coffee-bot` не передаёт модели произвольные таблицы или Telegram-историю.
Каждый запрос содержит только вопрос, Telegram user ID и технический
`conversation_id`, составленный из ID чата и пользователя. Поэтому контекст
уточнений хранится отдельно для личного чата и рабочей группы. Сервер помнит
15 минут только последний проверенный план (точки, период и тип данных), а не
текст переписки.
Вопросы о времени отдельных продаж доступны за один день и для одной или
двух названных точек. Время и напиток берутся из timestamped-выборки
Telemetron; текущая выборка явно ограничена безналичными продажами.
При недоступности ИИ все обычные кнопки, обслуживание и отчёты продолжают
работать.

Блок `К обслуживанию сегодня` объединяет данные Google Sheets с оперативной
сводкой шести действующих точек. Компактная моноширная таблица показывает
продажи вчера/сегодня и время последней безналичной продажи; состояние связи
вынесено отдельно, поэтому пауза в продажах больше не выглядит как `offline`.
Справа одна цветная точка показывает паузу продаж: зелёная — меньше 2 часов,
жёлтая — от 2 до 3 часов, красная — 3 часа и больше, белая — точка вне
графика. Длинного дублирующего блока предупреждений нет. Короткая гипотеза о
подаче кофе появляется только при жёлтой/красной паузе и последнем напитке,
который точно классифицирован как не содержащий кофе. Кофейный состав имеет
три состояния (`с кофе`, `без кофе`, `не определено`) и определяется только
по точному владельцем подтверждённому справочнику рецептов — без догадок по
названию или ИИ. Количество, время и напиток берутся из Telemetron, состояние
связи — из Vendista. Архивная точка `Бел2` остаётся в истории обслуживания,
но не включается в оперативный блок. Если онлайн-сервис временно недоступен,
текущая информация об обслуживании продолжает работать.

Последняя строка сводки ведёт на постоянную страницу Telemetron
`reports/sales-by-machines`, где после входа открывается актуальный отчёт
по продажам. Предпросмотр ссылки в Telegram отключён, чтобы сообщение
оставалось компактным.

## Проверки

- Проверка синтаксиса: `python3 -m py_compile bot.py`
- Тесты оперативной сводки: `python3 -m unittest discover -s tests -v`
- Линтер: `ruff check .`

## Безопасность

- Не коммить `.env` и `credentials.json`.
- В проде хранить ключ сервисного аккаунта вне репозитория, например в `/etc/coffee-bot/credentials.json`.
- Если токены или ключи попадали в публичный доступ, обязательно ротируй их.

## Подготовлено к выпуску

Доставка/покупка из обычного сообщения пишется в отдельный лист «Движения
товаров», а не прибавляется к физической ревизии. Одна строка на сообщение;
редактирование обновляет строку, отмена меняет статус. SQLite на постоянном
диске хранит операции и точные состояния Sheets до/после; серверный маркер
защищает повтор после потери HTTP-ответа. Идентичное повторное сообщение за
тот же день не считается новой доставкой.

Пример: «Макси обслужил. Довёз кофе 2 пачки, стаканы 100. Купил салфетки
2 упаковки за 180 ₽». Обслуживание использует существующий путь записи.
Суммы нового журнала информационные; отдельное движение не начисляет оплату
обслуживания или расходы. Существующий формат компенсации покупки воды
сохранён. Новые напоминания не добавлены.

Непонятные товары/количества требуют уточнения. Неизвестный источник
сохраняется явно; даже указанный источник сам по себе не списывает домашний
склад. Для расчётных остатков сервер учитывает только совместимые единицы
кофе/молока/шоколада/моки/стаканов после дня физического подсчёта. Неполнота
сообщений остаётся явной; отсутствие сообщения не считается нулём доставок.

Проверка: 146 тестов + 27 subtests; 23 теста нового сценария. Сервер проверяет
дату, точку, единицы, отмену, повторы, недоступность и неполноту журнала.
После merge требуется подтвердить deployment, версии и запись на изолированном
проверочном листе без сообщений сотрудникам и без изменения финансовых данных.

# Закупщик — Mini App

Статус 02.11.2026: локальная версия и черновой PR №35 подготовлены; в production не выпущен.

Проверка 02.11: 31 тест закупщика и смежного HTTP API прошёл. Мобильный обзор
отрисован при ширине 390 px в Chrome; блок обслуживаний показывает даты из
листа сотрудников без повторного ввода. Расчёт закупки текущего месяца
исправлен: уже прошедшие дни не включаются второй раз. Встроенный браузер
Codex не предоставил доступ к вкладке, поэтому мобильный вид проверен
локальным Playwright. Телефонный Telegram-клиент пока не проверен.

## Что доступно

- Обзор позиций первичной ревизии и БДР, включая отдельно «Раф банан», список действий, запасы по местам, последний месячный физический остаток и отдельно расчётное потребление.
- Средний расход по напиткам за последние 28 полных дней. Учитываются paid/free/test по официальному API Telemetron, каждый запрос ограничен 31 днём. Имена сопоставляются с рецептом конкретной точки, два подтверждённых варианта написания нормализуются явно.
- Расход по неизвестным напиткам не равен нулю. При неполной рецептурной карте полный прогноз отсутствует; показатель «от» показывает только распознанную часть.
- Потребность выбранного месяца и отдельное количество к покупке: для текущего месяца закупка покрывает оставшиеся дни, для будущего — весь месяц; добавляются защитный запас, пригодный остаток и только своевременные поставки, результат округляется до упаковки. Срок заказа учитывает срок поставки и запас в днях; просроченный или поздно приходящий заказ не закрывает раннюю нехватку.
- Параметры товара, ручная месячная оценка для расходников, оперативные заказы/получения/отмена. Состояние сохраняется в отдельной SQLite на постоянном диске. Повтор заказа/получения не дублирует событие. Возможный дубль полученного товара с внешним журналом останавливает оценку до сверки.
- История товаров из существующей книги «Закупки», ссылки на источники, их доступность и даты срезов. Финансовые таблицы читаются только с read-only scope.
- Личные уведомления в существующем боте: пользователь включает их сам в Mini App; отправка только владельцу, 09–20 МСК, тихо при неизменном состоянии. После неопределённого результата отправки слепого повтора нет.
- Telegram initData проверяется сервером: HMAC, срок входа, отдельный обязательный список `PROCUREMENT_OWNER_IDS`. Роль редактора выплат сама по себе доступа не даёт. В локальном просмотре доступна только работа с данными для чтения. В продакшн режима обхода Telegram-входа нет.

## Входы

Интеграция: Mini App слушает отдельный `PROCUREMENT_PORT=8081`; служебный API выплат остаётся на `OWNER_PAYROLL_API_PORT=8080` без публичного домена. При `PROCUREMENT_ENABLED=true`, корректном HTTPS `PROCUREMENT_URL` и явно заданном `PROCUREMENT_OWNER_IDS` владелец получает кнопку «Закупщик» в главном меню. Railway-домен закупщика должен указывать на порт 8081.

Локальный просмотр: `.venv/bin/python -m procurement.app --preview --port 8766`. Нужны существующие серверные Google/Telemetron credentials в окружении; секреты не передаются в браузер. Опциональный `--snapshot .procurement/connected-sheets.json` подставляет явно датированный срез книг, недоступных сервисному аккаунту, только в preview. В production такого fallback нет.

## Фактическая проверка источников 01.11

- Прямое чтение Google: первичная «Ревизия» и «Движения товаров» доступны. Сервисный аккаунт backend читает закупки октября. Рабочая книга рецептур для этого аккаунта недоступна; локальный просмотр использует датированный read-only срез через подключённый Google Drive. Для unattended production нужен доступ чтения к книге модели.
- Свежие продажи получены через существующие server credentials Telemetron. Плагин повторно подключён владельцем, чтение `get_points` подтвердило пять активных точек и две отключённые.
- После поправки владельца прочитан весь БДР → «Ревизия». За сентябрь склад дома есть: кофе 46, молоко 67, мока 20, стаканы 2730, отдельно «Раф банан» 48. Ранее источник ошибочно ограничивался первичной книгой бота. Теперь оба источника сопоставляются по ячейкам; одинаковым значениям можно привязать физическую дату из первичного отчёта. Для домашних значений без подтверждённой физической даты она не выдумывается. В БДР заголовок сентября написан «31.09.2026»; читается как метка месяца, исходная таблица не исправлялась.
- Для части продаж PRO LV названия `item`, `Item` не соответствуют подтверждённым рецептам из рабочей книги. Не назначать им рецепты по догадке. Для эспрессо владелец подтвердил одну таблетку 10 г. Нормативный расход по распознанным напиткам показывается отдельно; полный расход и количество к покупке требуют уточнения сопоставления/остатков.
- Полнота журнала развозов не подтверждена. В отчёте это явно видно; отсутствие строки не считается доказательством отсутствия доставки.

## Что остаётся до выпуска

1. Просмотреть локальный интерфейс; текущая версия доступна на `http://127.0.0.1:8766/procurement/` во время работающего процесса.
2. Доступ читателя к книгам рецептур и закупок выдан сервисному аккаунту бота 02.11; прямое чтение обоих листов проверено. Ссылки на четыре переменные Telemetron и ID владельца подготовлены в ожидающих изменениях Railway, но ещё не действуют.
3. Перенести уже присланные числовые остатки октябрьской ревизии и сопоставить неизвестные напитки. Отмечать обслуживания заново не требуется: живой лист `Обслуживание` уже читается. Параметры срока поставки, защитного запаса и упаковок вводятся владельцем; нулевые значения по умолчанию не подставляются.
4. После просмотра подготовленного PR выпустить проверенную версию и применить ожидающие переменные Railway. HTTPS-домен создан на отдельный порт 8081, но Mini App ещё не отвечает до выпуска кода. Уведомления не отправлялись.

Фотографии из группового архива, автоматическое распознавание произвольных фото и групповой ввод общего отбора без назначения пока не подключены к новому интерфейсу. Существующие текстовые ревизии и движения сохраняют свой путь; новые подтверждённые записи из них читаются при обновлении.
